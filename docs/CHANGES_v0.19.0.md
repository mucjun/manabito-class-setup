# v0.19.0（2026-11-21）講座のプロファイル・この講座で入れるアプリ・プロファイルの設定

淳さんの要望：今のプロファイルを基準に、「事務系」（Office・Adobe Acrobat Reader・Paint.NET）と「WEB系」（Office・Adobe CC・Adobe Acrobat Reader・VS Code）を作り、
プロファイルの設定ができるメニューを設ける。追加のアプリはトグルにせず、プロファイルで決める（設定し忘れを防ぐ）。

- profiles：standard.json を「基準」に。jimu.json「事務系」を追加。web.json を「WEB系」に。キー extraApps（Id のカンマ区切り）・pdfDefault。
- scripts\extra_apps.txt（目録）、scripts\modules\extraapps.ps1（点検・winget で入れる・Acrobat の初回の確認を止める・PDF の関連付けのポリシー・VS Code の日本語化）。
- deploy.ps1・oneclick.ps1 に -ExtraApps。準備の一覧に「この講座で入れるアプリ」（Office の次）。
- ［設定をそろえる］に「この講座のアプリの設定」（複数の行を返せるように Invoke-ApplyAll を直した）。
- 画面：講習の準備タブに「この講座のアプリ」の行、プロファイルの横に［設定…］、プロファイルの設定の窓。窓の最小の幅を 1,180 に。
- プロファイルを 2 か所から読む（アプリの profiles と %ProgramData%\ManabitoClassSetup\profiles）。選んでいたものを読み直しのあとも選ぶ。
- office.xml などは、プロファイルと同じ場所に無ければアプリの profiles から使う（設定画面で作ったプロファイルのため）。
- ［履歴を消す］のサインインの消去に Visual Studio Code を追加。

## 自分でのコードレビューで直したこと

- winget の引数の変数名を $args にしていた（PowerShell の特別な名前）→ 別の名前に。
- 今回入れたかの判定を、説明の文の中身で行っていた → はっきりした目印で。
- ［設定をそろえる］が 1 項目 1 行の前提だった → 複数の行を受け取る。
- winget の「PC 全体に入れる」が使えないアプリ → 指定を外してもう一度だけ試す。
- 設定の窓：Tab で項目を移れるように（IsDialogMessage）、保存を待つ間の二度押しを防ぐ、待つ間は描き直しだけを行う（ほかの確認の窓を出さない）。
- 保存の部品の場所の確かめで、区切りの文字に頼っていた → どちらの区切りでも正しく確かめる。
- 「この講座のアプリ」の行で［設定…］の場所を「右上」と誤って書いていた → 「プロファイルの横」。
- 1 段目のボタンが増え、窓の最小の幅（1,130）では切れる → 1,180 に。
